# 07 — Preparar una entrega del proyecto

> [Volver a `scripts/`](../) · [Política de datos](../../DATA_POLICY.md) · [Mapa completo](../../REPOSITORY_MAP.md)

Esta etapa prepara una **copia del proyecto para compartirla con un público determinado**, respetando las reglas de visibilidad definidas en `publication.yml`.

En el template se distinguen tres tipos generales de entrega:

- **pública:** solo material autorizado para distribución abierta;
- **interna:** material para colaboradores autorizados;
- **privada:** material de trabajo más amplio, siempre respetando que los datos `restricted` no deben entrar al historial de Git.

Una “release” o **entrega versionada** es una copia identificable del proyecto en un momento determinado. Puede utilizarse para entregar resultados a un consultor, acompañar un informe, archivar una versión o publicar material reproducible.

Antes de preparar una entrega:

1. revise `publication.yml` y `DATA_POLICY.md`;
2. compruebe que no haya credenciales ni información restringida;
3. actualice el inventario de archivos y las tablas de trazabilidad;
4. identifique la versión del código y, si corresponde, la corrida certificada.

La privacidad de un repositorio GitHub y la autorización institucional para compartir datos son cuestiones diferentes; ambas deben cumplirse.
